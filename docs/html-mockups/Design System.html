Design System

Calm, precise, confident.

Ledgerly's design language is Linear meets VS Code meets a well-designed terminal app. The interface should feel like reading prose, not flying a spaceship.

Philosophy

Three rules that override every other decision.

01
Hairlines over shadows.
Use 1px borders to separate surfaces. Reserve shadows for floating elements only — modals, popovers, dropdowns.
02
Weight and background over color.
Reach for color sparingly. Most emphasis comes from font weight or a subtle background tint, not from hue.
03
Whitespace is a feature.
Information density is fine; cramped is not. Every element should have room to breathe.

Accessibility

Non-negotiable baseline. Ledgerly is macOS-first but the same rules apply everywhere.

ConcernRule
ContrastWCAG AA — 4.5:1 for body, 3:1 for large text. Every token pair in this doc meets it.
Focus ringsoutline: 2px solid var(--color-accent) · outline-offset: 2px
KeyboardEvery action reachable by mouse must be reachable by keyboard.
Reduced motionDisable transitions; opacity-only fades. tokens.css already zeros durations under the media query.
Screen readersSemantic HTML — <button>, <nav>. ARIA only when no semantic element fits.
Touch targetsMinimum 32px tall on interactive elements.

File organization

Where tokens and styles live in the codebase.

src/
├── styles/
│   ├── tokens.css       ← All design tokens as CSS variables (source of truth)
│   ├── globals.css      ← Resets, base typography, body styles
│   └── components/      ← Per-component styles (use tokens, never hardcoded values)
└── components/
    └── ui/              ← Primitive components (Button, Input, Badge, etc.)

Rules

  1. Components reference tokens via var(--token-name) only. No hardcoded hex, no hardcoded pixel values for spacing.
  2. If a component needs a value that isn't in tokens.css, propose adding the token first.
  3. Per-component CSS lives in src/styles/components/<name>.css or co-located with the component file.
