Diurnum sends only the following data to your adapter:

  • transaction.payee— the raw merchant string, normalized
  • transaction.amount— signed decimal, currency-tagged
  • transaction.date— ISO 8601, no time component
  • account.kind— e.g. checking, credit; never the account number
  • categories[]— the list of your category names, for the model to pick from
  • recent_rules[5]— last 5 matching rules, as few-shot examples
Never sent: account numbers · balances · attached documents · workspace name
